**019fd504 做对了的事：**
- 把 Streamlit 迁移为纯静态站，解决了部署和加载速度问题

4. **优化结果页只剩两张图 + 两个 GIF**：原来有速度差值图、偏航前后动画对比，现在信息量不足。

## 二、问题根因分析

019fd504 的核心决策是"纯静态 + 零依赖"——这本身是对的（部署简单、加载快），但执行中犯了一个致命错误：**把"零后端"等同于"零交互库"**。

正确的理解应该是：
- ✅ 零后端 = 不需要 Python/Streamlit 服务器
- ❌ 零依赖 ≠ 不能用 CDN 加载的 JS 库

Plotly.js、Three.js、ECharts 等都可以通过 CDN `<script>` 引入，依然是纯静态部署——用户打开 HTML 就能跑，Cloudflare Pages 照样托管。019fd504 舍率地抛弃了这些，全部手写 SVG，导致 3D 能力和视觉品质同时崩塌。

## 四、技术架构决策

### 4.1 核心原则：纯静态 + CDN 交互库 = 最优解

```
site/
├── *.html              # 纯 HTML（Cloudflare Pages 直接托管）
├── css/style.css       # 全局样式
├── assets/
│   ├── data.js         # 数据（build_data.py 生成）
│   ├── js/
│   │   ├── interp.js   # 代理模型接口
│   │   ├── charts.js   # SVG 辅助图表（保留用于简单场景）
│   │   └── app.js      # 全局交互逻辑
│   └── img/            # 流场图等
└── lib/                # CDN 本地缓存（可选，或直接用 CDN URL）
```

**CDN 引入方案**（在 `<head>` 中）：
```html
<script src="https://cdn.plot.ly/plotly-2.35.2.min.js"></script>
```

这样：
- 依然是纯静态部署，不需要后端
- 恢复全部 3D + 交互能力
- Cloudflare Pages + CDN 缓存 = 极速加载
- 用户离线时 data.js 已内嵌数据，Plotly.js 从 CDN 缓存读取

### 4.2 不做的事

- ❌ 不回退到 Streamlit（部署慢、卡顿、不可控）
- ❌ 不引入 Node 构建链（违反纯静态原则）
- ❌ 不自写 WebGL 3D 渲染器（Plotly.js 已够用且成熟）
- ❌ 不改数据接口契约（已固化，各组替换零改动）

## 六、风险与约束

| 风险 | 缓解 |
|---|---|
| Plotly.js ~3.5MB，首次加载可能慢 | Cloudflare CDN 缓存 + gzip 后 ~1MB；可异步加载 |
| 数据全在 data.js（~968 行），未来真实数据更大 | 可拆分为多个 JSON + fetch；当前规模无问题 |
| 3D 渲染在移动端性能差 | 可检测设备，移动端降级为静态图 |
| numpy 在沙箱非持久 | render_assets.py 生成 PNG 后提交到 Git，无需运行时 numpy |
